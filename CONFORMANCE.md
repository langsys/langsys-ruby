The spec blob is re-derived every time this file is written (`git -C ../langsys2 rev-parse
f5568b88:docs/sdk-spec.mdx`), and the file is checked in the build by the same code
`rake conformance:check` runs: the header, the profiles, all 113 rule ids exactly once, the
status and tier vocabulary, and a named mutation on every row that claims runtime behaviour.

**Tiers.** `contract` rows assert on status and on the state the double holds after the SDK
acted, read back through `GET /__fixture/state` or a second catalog read. An absence is evidence
only where the double would have accepted the action, so every absence drifts the double's world
after the SDK learned its capability, with a control acting in the drifted world. `n/a (pure)`
covers what the SDK computes with no server answer to assert against: in-process behaviour,
cross-implementation identity fixtures, "never attempt" clauses proven at the transport seam,
isolation, and the meta-rules CONF-2 and CONF-3. `live` rows also run against the real server.

## What surfaced while writing this

- `t()` returned the raw ICU source of a translated `select` or `plural` when the caller passed
  no params; recovery now runs on every call, with or without params (ICU-1, ICU-3, ICU-4).
- The page walk dropped a block's own translatable attributes and every top-level inline or void
  element, and one-token fragments were blocks rather than phrases; the walk now registers TOK-6
  units on every path.
- A failing catalog fetch was repeated on every lookup: an eleven-token page made eleven failing
  requests. The failure is now remembered per locale (CACHE-2).
- One request's post-response flush could send another in-flight request's misses. Misses
  recorded inside a request scope now wait for that scope's response (SRV-3).
- Mutation found tests that could not fail. Each is now a committed test: CID-4's decline vector,
  REG-11's positive control, `sync`'s structural check, a status:false catalog response, a `.po`
  continuation line, and the listing command's second run against an idempotent server.

## Parser residuals

Pinned by `identity_paths_801_spec.rb` on both Nokogiri parsers, guarded on libxml2 2.13.x so a
version bump forces a re-measure. The C0 strip makes these id-neutral where the text reaches the
SDK; the last two are the cases no strip can close.

| Input (Nokogiri 1.19.4, libxml2 2.13.9) | `Nokogiri::HTML` and `Nokogiri::HTML.fragment` |
|---|---|
| U+0001–0008, 000B, 000C, 000E–001F in text, raw or as references | dropped by the parser |
| lone CR / CRLF | kept raw; both collapse to one space |
| raw U+0000 in text | becomes U+0020 |
| `&#x00;` in text | dropped |
| `&#x1C;` inside an attribute value | truncates the value: `title="a&#x1C;b"` reads `a` |

Parse model, vendored `parse-model-reference.json` (langsys-php-sdk 5400248): block-path tokens
equal libxml2's recorded tokens on 7 of 7 inputs and agree with the JS family on 5 of 7; the split
is the raw-text `textarea` and `title` rows.

## Declared postures

**GATE-3, process level.** The write decision lives on the client instance and is never
persisted: stripped before any cache write (GATE-4), never read back from one, compared by
recency across its two sources. A Ruby client outlives a request, so
`Client#reset_write_decision!` drops it at a request boundary; langsys-ruby-rails wires that.

**SRV-3, request scopes.** `Langsys.begin_request_scope` / `end_request_scope(scope)` /
`request_scope { }` are module-level, so a host opens a scope before any client exists, and the
current scope is fiber-local. A scope that is never ended holds its misses until the shutdown
flush.

**REG-3, wrapper obligation.** `flush_on_shutdown` runs from `at_exit` with `auto_flush: true`,
which does not run on an OOM kill, `SIGKILL` or a hard timeout. The reliable path is
`Client#flush_pending` after the response, wired by the framework binding.

**Grant lane, affirmative non-participation.** No `X-Write-Grant` header is ever sent, asserted
case-insensitively over the assembled header set. The read-key short-circuit in
`Client#write_enabled?` is sound only while that holds; the test's failure message says what to
remove if grant support lands.

**GATE-8, the two meanings of absence.** `write_enabled` is absent from a pre-capability server
or from a payload this SDK cached. The fallback applies to `read` and plain `write` keys only;
`ip_write` pays a live authorize.

**CID-3, the JS code-unit shape is not tolerated.** Code-unit ids were minted by browser SDKs,
whose tolerance lives in the browser core's own exports.

## Gaps, ranked by cost

1. **MIG-9** — no one-time import, so a migrating app's existing translations are machine-translated
   again rather than kept. Cost of translation, once per migration. Waits on the 907 merge.
2. **Parser residuals** — NUL and a C0 reference inside an attribute still depend on libxml2 below
   2.14. Identity for rare content; closed by an HTML5 parser, not decided here.
